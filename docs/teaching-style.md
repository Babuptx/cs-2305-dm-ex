For induction lessons, distinguish the hypothesis from the target, mark where the hypothesis is used, justify every base and index range, and explain why a smaller object retains the theorem's assumptions. Finite example tests supplement editorial proof review; they do not establish claims for infinitely many integers.

For recursion lessons, distinguish a definition from an algorithm, specify domains and all base cases, and explain the decrease that makes each recursive dependency valid. Structural proofs follow every constructor. Algorithm correctness includes preservation of all items or the promised search result, while efficiency is analyzed separately with its operation model stated.

For program correctness, distinguish partial correctness from termination. State the execution model and input domain, track old and new assignment values, and show initialization, preservation, exit, and termination separately. End-of-chapter pages use original retrieval checks, worked practice, and project briefs aligned with the source categories; they do not reproduce its complete numbered exercise list.

For counting lessons, define one outcome before choosing a formula. State whether order, roles, repetition, and leading zeros matter. Justify disjoint cases for addition, constant branch counts for multiplication, membership in the counted universe for subtraction, and uniform multiplicity for division. Stop counting-tree branches when the process ends. Keep fictional counting models distinct from current real-world allocation or syntax rules.
