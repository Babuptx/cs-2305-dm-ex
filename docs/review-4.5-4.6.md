Section 4.5 covers modular hashing, collisions, linear probing, full-key comparisons, wraparound, full tables, duplicate keys, and the lookup/deletion distinction. It explains deterministic linear congruential generators, finite-state repetition, transients versus cycles, primitive-root multiplicative generators, the zero trap, and scaling to [0,1). It then covers even parity; twelve-digit UPC/GTIN checks; single-substitution and transposition guarantees and counterexamples; the legacy ISBN-10 weighted sum modulo 11 and X; its error-detection proofs; and an explicitly identified ISBN-13 bridge. Checksum validity is distinguished from error-free data, authentication, and official allocation.

Section 4.6 covers alphabet encoding, shifts, affine inversion and collisions, frequency-analysis limitations, consistent read-from transposition and inverse permutations, padding ambiguity, the cryptosystem five-tuple, correctness versus security, shared/public-key roles, hybrid designs, and authenticated public keys. RSA coverage includes key construction, strict message bounds, fixed-width encoding, repeated-squaring encryption, decryption for all residues via Fermat and CRT, and checked toy code. Further units cover security limitations, Diffie–Hellman arithmetic, authentication and key derivation, signatures versus confidentiality, raw-signature forgery as a mathematical counterexample, multiplicative homomorphism versus addition, and modern homomorphic-encryption context. Practice and an optional finite-test project close the lesson.

Source qualifications are explicit in the teaching rather than copied as errors. The page 308 ISBN argument must use the weighted sum modulo 11, not the unweighted modulo-10 expression appearing in its prose. The transposition formula on page 313 and the worked direction on page 314 use different conventions; this lesson consistently defines c_i = p_sigma(i), with one-based read-from order [2,4,1,3] and inverse [3,1,4,2]. RSA plaintext blocks require 0 ≤ m < n, not m ≤ n. The proof includes multiples of either prime, not just coprime messages. The homomorphic product reduces modulo the RSA modulus n. Inverse-key arithmetic solves for d as the inverse of e. Outdated ISBN descriptions, general claims about computer random generators, factoring as the only possible RSA attack, unconditional Diffie–Hellman security, quantum timelines, and blanket claims that homomorphic encryption is unavailable or impractical are not repeated.

The same sources appear in the appropriate lesson references. The RSA/Diffie–Hellman examples deliberately use tiny public parameters and are identified as mathematical demonstrations, not deployment recommendations. No real credentials, personal identifiers, secure-key generation, or production cryptographic implementation is introduced.

Code contracts are visible in the lessons. Hash keys and LCG arithmetic use BigInt; table sizes and step counts are bounded Number integers. Hashing distinguishes null from zero and detects full tables; duplicate keys are idempotent. LCG output includes the seed. Check-digit functions preserve string leading zeros and reject malformed characters and lengths. ISBN checks validate arithmetic and format, not registry allocation. Affine keys are normalized safe integers; unsupported text is rejected rather than silently removed. Transposition uses a dense permutation of 1 through block width and requires full uppercase blocks without automatic padding. Pair encoding preserves fixed two-letter width and rejects invalid letter codes. Toy RSA uses distinct verified primes at most 10,000, rejects noninvertible exponents, and requires every message below n. Dependencies on the earlier modular-power, primality, extended-gcd, normalization, and inverse functions are named. The inverse helper's null result is explicitly checked before returning a key.
